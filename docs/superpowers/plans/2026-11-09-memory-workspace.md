# Активная память 1.3.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task; one final independent review.

**Goal:** Внедрить одобренный интерактивный макет по «текст (3).txt» поверх 1.2.1 и опубликовать в прежнем репозитории.

**Architecture:** Сохранить core/engine/host/order/view-state/index. UI строит карточки и статус только по снимку движка, без собственного отбора воспоминаний. Глобальная кнопка использует существующие enabled/inject, не сбрасывает флаги архива. Общие вкладки доступны без сессии чата; архивные инструменты остаются привязаны к открытому чату.

**Tech Stack:** Существующие ES modules, native dialog/buttons/details, изолированный CSS, Node tests, Playwright в отдельной ST 1.19.0.

**Spec:** «текст (3).txt» и показанный/подтверждённый пользователем макет «Омут памяти — активная память». После показа пользователь ответил «давай».

## Global Constraints

- Не менять генерацию, промпты, формат архива, UUID/связи, порядок и правила блокировки памяти.
- Сохранить компактные границы, ручной выбор/порядок арки и все существующие технические действия.
- Основная палитра #101e33 / #1b3555 / #b79c73 / #f2ebdd, мягкий зелёный фактически активным статусам, серо-синий архивным.
- Статус «Активна» означает присутствие в допущенном движком блоке, а не только e.active.
- Прежний лимит блокирует весь блок: не вводить новый алгоритм пропуска записей.
- Обновление и публикация уже разрешены; повторное согласование не требуется.

## Review Focus

- Глобальное отключение и включение не изменяют JSON архива и восстанавливают прежнюю подборку.
- Отключённое расширение, лимит, отсутствующие источники и конфликт арок не дают ложного зелёного статуса.
- Без чата доступны все операции промптов и общие настройки; не создаётся фиктивный архив.
- Связанная сводка не дублирует активную арку; быстрое включение доступно после отключения арки.
- Узкие/короткие экраны, касания и кеш прежнего HTML; X и соседние расширения доступны.

## Ledger

- Причины: memoryView уже использует верный снимок, но прежние названия/подача; кнопка «Отключить всю память» вызывает disableAll() и сбрасывает выбор записей; render() блокирует общие вкладки при отсутствии сессии.
- Ruling: первый вход через общее меню открывает «Активную память»; явные шесть кнопок настроек сохраняют свои вкладки.
- Ruling: источник, уже замещённый активной аркой, не получает вводящую в заблуждение кнопку добавления: пояснение и disabled-кнопка до отключения арки. Существующее ручное снятие флага не блокируется.
- RED→GREEN: проверка первого входа выявила, что штатное wand-меню создаётся ST после загрузки расширения. Добавление пункта перенесено на APP_READY с немедленной попыткой и защитой от дублей; используется существующее событие ST, без наблюдения всего DOM.
- Проверено: 69 unit-тестов, новый сценарий обоих движков, точное копирование/просмотр, глобальное выключение после reload, полное совпадение архива, исходные промпты, manager/memory/compact/settings и полный integration. Ревью основного изменения и меню — без замечаний.
